# 公開デモを運用する

誰でも触れる、合成データだけの使い捨てのデモです。招待制のhosted（[hosting.md](hosting.md)）とは別の動かし方で、`meibo hosted ROOT serve --public-demo` で起動します。全員が同じ1組織を共有し、操作がなければ自分で終了して、次の起動で初期状態に戻ります。

## 何をして、何をしないか
- 営業の主な流れ（架電モードで不在の再架電を予約、商談の段階、月次の着地予測）を、そのまま触れます。初期データは、起動した日付を基準に毎回作ります。月次集計は、受注32万円・受注率50%・確度加重見込み65万円・着地予測97万円から始まります。
- 社名はすべて先頭に「合成・」を付け、電話番号は `000-0000-NNNN`（どの体系にも存在しない形）にします。生成器の社名と電話は、実在のものと偶然一致しうるためです。
- パスワードログイン、CSV取り込み、問い合わせフォーム、メール・予定の連携、利用者や所属の変更は提供しません。理由は、パスワードを公開で受けると失敗の上限で全員が締め出されること、取り込みと外部連携が悪用の入口になることです。
- 入室は「デモを開く」だけです。起動ごとに1つの共有 session（組織 `demo` の編集者）を作り、入室した全員に同じものを渡します。訪問者ごとの session は作らないので、件数の上限も、古いものの追い出しもありません。入室は全体で1分に300回までで、接続元ごとの制限は前段のWorkerが受け持ちます。
- ログアウトは、その人のCookieを消すだけで、共有 session は残します。1人のログアウトで全員が締め出されないためです。
- デモでは監査の記録を書きません（入室・ログアウト・権限の拒否を含む）。全員が同じ利用者なので、記録しても区別の意味がなく、保存量だけが増えるためです。

## 起動
```sh
meibo hosted ROOT serve --origin https://<公開ドメイン> --bind 0.0.0.0:4317 --public-demo [--demo-contact <連絡先URL>]
```
- ROOTは、存在しないか空のディレクトリだけです。中身があれば起動を拒否します（実データの上で動かさないため）。`--access-config`・遠隔保存とは併用できません。
- 自己終了：アイドル15分（`--demo-idle-seconds`）、起動から6時間（`--demo-max-uptime-seconds`）、処理が10秒止まったとき（`--demo-stall-seconds`）。いずれも既定値で、引数で変えられる。保存先の合計が上限（32MiB）以上のまま続いたときも終了します（測定は2秒ごと、10秒続いたら）。終了前に `demo-reset reason=idle|uptime|storage|stalled` を1行出し、アイドル・上限時間・保存量は終了コード0、止まったときは70です。**実行先が、終了したら再起動する前提です。**<!-- ok -->
- 上限：POSTの本文は64KiB（`Content-Length` 必須）。件数は、取引先1,000・活動5,000（取消も1件と数える）・商談200・独自項目20・担当者2,000・仕事5,000・架電リスト50。保存先の合計は32MiB。件数を超える作成は403（`demo_limit`）、保存量を超える書き込みは507で断ります。

## 守りの考え方
- tiny_http はソケットのタイムアウトを持たず、1件ずつ順に処理します。本文を遅く送る接続が1本あるだけで、全員の応答が止まります。本番では、前段のWorkerが本文を最後まで受け切ってからコンテナへ渡します。それをすり抜けても、処理が止まればプロセスが自分で終了します。
- **公開の条件は、前段が本文を受け切り、宣言した長さと一致する要求だけをアプリへ渡すことです。** アプリを直接インターネットへ出す構成は支持しません。tiny_http は、拒否した要求の本文も読み捨ててから次へ進み、`Connection: close` もアプリからは付けられません。巨大な長さを宣言されると、確保に失敗して落ちることもあります。
- 全員が同じデータを共有するので、他の人の操作で表示が変わります。入口と画面に明記しています。1人がデータを消したり、大量に書き込んだりもできます。復旧は初期化（自己終了と再起動）に任せます。
- 初期データは起動した日付を基準に作ります。稼働中に日付や月をまたぐと、「今月」の集計や再架電の期限の見え方は変わります。

## イメージと配備
- イメージ：`docker build --target demo .`。`MEIBO_DOMAIN`（必須）、`PORT`（既定4317）、`MEIBO_DEMO_CONTACT`（任意）を受け取ります。ピークのメモリは約45MBです。
- Cloudflare Containers と Worker：[deploy/demo/cloudflare/README.md](../deploy/demo/cloudflare/README.md)。Containersの利用にはWorkers Paid（月$5）が必要です。常時起動した場合の最悪は月$9前後（公式の料金表の単価からの概算。休止すれば含まれる使用量の範囲で$5）です。Containersの使用料には、自動で止まる上限がありません（Cloudflareの費用の上限はWorkersとDurable Objectsだけが対象で、アカウント全体に効くため、同じアカウントの他のWorkerも止まります）。予算アラート（メールのみ）を設定し、止めるときは [OPERATIONS.md](../deploy/demo/cloudflare/OPERATIONS.md) の停止の手順（設定値1つ）を使います。
- 実行先の候補の比較と、費用・停止の判断：`.kiro/specs/public-demo/design.md`。

## 検証
- Rustの試験：`cargo test -p meibo-app --locked hosted`・`--test hosted`。
- 実ブラウザ（幅390・768・1440px）と、HTTPの境界の検査：`deploy/demo/browser/`。実バイナリは `MEIBO_BINARY=<meibo> npm test`、コンテナは `MEIBO_DEMO_BACKEND_PORT=<ポート>`、配備後の公開URLは `MEIBO_DEMO_URL=https://…` で、同じ試験を向けます。CIは `.github/workflows/demo-image.yml` です。
- 公開前は、公開URLに同じ検査を流し、1つでも失敗したら公開しません。

## 運用者の責任
- 入力された内容は、初期化で消えます。ただし、実行先（Cloudflare）には通信の記録が残り得ます。入口に明記しています。
- 実データを入れないでください。このデモは合成データを前提に作っており、個人情報や営業活動に関する法令への適合を保証しません。
