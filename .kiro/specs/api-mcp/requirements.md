# APIとMCPの要件

2026-10-26本人の未完了機能実装・一般公開指示に基づく。画面で行える企業検索と活動記録を外部クライアントからも使う。

## 1. 共通の営業操作

1.1 When クライアントが一覧または社名検索を要求する, the meibo shall 画面と同じ条件・並び順・上限1〜200・続き位置で企業を返す。
1.2 When クライアントが企業詳細を要求する, the meibo shall 未消去の企業だけを返し、担当者連絡先と個人事業の個人項目を明示指定なしに開示しない。
1.3 When 記録権限のあるクライアントが活動を送る, the meibo shall 既存の入力検証・除外状態・次回対応の保持/設定/解除を適用し、成功した記録を再読込後も返す。
1.4 If 入力に未知項目・型違い・重複条件・不正な識別子が含まれる, the meibo shall 保存せずに入力エラーを返す。
1.5 If 書込み応答を受信できない, the meibo shall 自動再送せず、利用者が詳細の履歴で結果を確認できる契約を示す。
1.6 When 公的データ由来の企業を返す, the meibo shall 供給元・基準日・出典表示・加工表示をHTTPとMCPの両方へ同じ内容で含める。

## 2. HTTP入口

2.1 When クライアントが公開v1のパスを利用する, the meibo shall 既存画面用のパスを維持して版付きの一覧・詳細・活動記録を提供する。
2.2 While HTTP利用者が認証・組織・権限の検査を受ける, the meibo shall v1入口にも同じ共通境界を適用し、入口から任意の保存先や組織を選択させない。
2.3 If HTTP操作が対応しないmethod・path・サイズである, the meibo shall それぞれ405・404・413を返し、内部パスや保存エラーの詳細を開示しない。

## 3. MCP入口

3.1 When MCPクライアントが現行版の発見または要求を送る, the meibo shall 2026-07-28版のリクエストごとの必須metadataと結果を扱い、未対応版を対応版一覧つきで拒否する。
3.2 When 従来版クライアントが初期化する, the meibo shall 2025-11-25版の初期化・通知・要求の順序を扱い、初期化前の業務操作を拒否する。
3.3 When クライアントがtool一覧または呼出を要求する, the meibo shall 一覧・検索・詳細・活動記録を同じ共通操作へ結び、読取/書込と非冪等性をtool注釈へ示す。
3.4 While 書込の明示起動オプションが無い, the meibo shall 活動記録toolを提供せず、直接の書込tool呼出も拒否する。
3.5 When 入力が改行で区切られる, the meibo shall 1行ごとに1つの要求を扱い、標準出力へJSON-RPC以外を出さず、入力終了で終了する。
3.6 If 不正JSON・通知・未知method・入力上限超過を受ける, the meibo shall 規格に沿ったエラーまたは無応答を返し、上限超過行全体をメモリへ保持しない。
3.7 When toolの実行に失敗する, the meibo shall 通信のエラーと業務のエラーを区別し、失敗した入力・企業内容・認証値をログへ出さない。

## 4. 検証

4.1 When 実装を検証する, the meibo shall 合成データだけを使い、2系統のversion・HTTP境界・個人情報既定・入力失敗・書込禁止・保存後再読込を試験する。

## 境界
HTTP認証/組織分離はteam-access、CRM実DBの接続はpublic-data-importersの契約へ従う。遠隔MCP用のHTTP transport、公開signup、独自のAI推論は含めない。
