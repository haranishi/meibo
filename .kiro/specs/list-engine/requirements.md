# list-engine の要件案

## Introduction
営業リストから新規開拓する営業（個人・小チーム）が、数百万社を持っても待たされずに、絞り込み・検索・記録・まとめて操作できる土台を作る。画面・取込・外部連携は、この土台の検索口を呼ぶだけで速さを引き継ぐ。「速さの門（Performance Gate）」は、速さの目標を測定で守らせる仕組みを指す。

## Boundary Context
- **In scope**: 企業・担当者・活動・リストの保存と取り出し、絞り込み・並べ替え・件数・社名検索、活動の記録、一括操作、個人情報の消去、合成データの生成、速さの門。
- **Out of scope**: 画面、CSVの取込と書出、API・MCP、認証と権限、利用者が定義する項目（custom-fields）、企業の統合、実データの取込、メール等の送信。
- **Adjacent expectations**: csv-import-export・call-mode・web-ui・api-mcp は、この仕様の検索と追加の口だけを使う。実データの権利判断は `docs/legal/rights-check.md` が持つ。
- **速さを宣言した形（最低限）**: 絞り込みは、(1) 地域（都道府県または市区町村）→業種→状態→電話の有無、(2) 地域→状態→電話の有無、(3) 業種→状態→電話の有無、(4) 状態→電話の有無、(5) 電話の有無のいずれかを、先頭からいくつか指定する形。ほかに (6) 担当営業と次回対応日以前、(7) 次回対応日以前（どちらも次回対応日の昇順）、(8) 絞り込みなしの最終活動日の降順、(9) 絞り込みなしの登録順。各項目は単一値の一致を最低限とし、形の先頭の項目は10値までの複数値も含む。(1)〜(5) の並びは形ごとに決まる安定した順で、設計が公開する。設計は広げてよいが、狭めるには仕様の更新承認を要する。
- **用語**: 社名検索の文字数は、正規化後（全角半角・かな・大文字小文字の違いをならした後）の文字で数える。個人情報の項目は、担当者の氏名と個人の連絡先、個人事業の企業の名称・代表電話・ホームページ。
- **測定の約束**: 時間の目標は、すべて95パーセンタイル（30回以上）で、公開口の呼び出しから結果の受け取りまでを測る。基準環境は Apple M4 Pro・メモリ48GiB で、合成4,445,898社を入れる。
- **目標値の扱い**: 初期値は予備測定（`.agent-harness/runs/2026-10-22-sqlite-spike/`）の実測に余裕を持たせたもの。実装後の実測が目標の5分の1以下の項目は、目標を実測の3倍へ縮める更新案を出す。緩める変更も縮める変更も、仕様の更新承認を要する。他の環境の目標は、実測してから決める。

## Requirements

### Requirement 1: 企業を法人番号つきで正しく登録できる
**Objective:** 営業担当として、日本の企業を取り違えず、二重に持たずに管理したい。
1. When 法人番号つきで企業を登録または更新する, the List Engine shall 13桁の数字とチェックディジットを検証し、不正な番号は理由を示して受け付けない。
2. If 更新対象以外の企業がすでに同じ法人番号を持つ, then the List Engine shall 二重に登録も更新もせず、既存の企業を示して知らせる。
3. When 法人番号を持たない企業（個人事業など）を登録する, the List Engine shall 番号なしで保存し、後から更新で番号を付けられるようにする。
4. If 企業名が空である, then the List Engine shall 登録も更新も受け付けず、理由を示す。
5. The List Engine shall 企業名を入力どおりの表記で保持し、正規化のために書き換えない。
6. When 企業を登録または更新する, the List Engine shall 値の出典と基準日を企業に紐づけて保持し、取り出すときに一緒に返せるようにする。
7. The List Engine shall 企業の所在地（都道府県・市区町村）・業種・代表電話・ホームページ・担当営業・状態（未着手・対応中・商談・受注・見送り・除外）を保持し、更新できるようにする。
8. The List Engine shall 法人番号と電話番号を数値として扱わず、先頭の0を失わない。

### Requirement 2: 企業・担当者・活動の関係をたどれる
**Objective:** 営業担当として、企業ごとに担当者とやり取りの履歴を見たい。
1. When 担当者または活動（架電・訪問・メール・メモなど）を登録する, the List Engine shall 担当者は1つの企業に、活動は企業に（任意でその企業の担当者にも）紐づけ、企業ごとに一覧できるようにする。
2. When 企業の詳細を求める, the List Engine shall その企業の担当者と活動を、日時の新しい順（同時刻は記録した新しい順）に返す。
3. If 存在しない企業や担当者への紐づけ、または別の企業の担当者への紐づけが求められた, then the List Engine shall 受け付けず、理由を示す。

### Requirement 3: 数百万社でも一覧の先頭と件数がすぐ出る
**Objective:** 営業担当として、445万社から条件に合う先を、待たずに見たい。
1. When 速さを宣言した形で一覧を求める, the List Engine shall 先頭50社を10ms以内に返す。
2. When 速さを宣言した形で次のページを求める, the List Engine shall 直前のページの続きから、ページの深さによらず10ms以内に返す。
3. If ページを送っている間に企業が追加または更新された, then the List Engine shall 並びの基準値と絞り込みへの適合が変わらない企業を、二度返さず飛ばさない。
4. When 速さを宣言した形で厳密な件数を求める, the List Engine shall 100ms以内に返す。
5. When 速さを宣言していない形で絞り込み・並べ替え・件数を求める, the List Engine shall 遅い条件であることを結果に示し、速さの門が測る代表的な遅い条件では2秒以内に返す。
6. If 許可されていない項目や演算が指定された, then the List Engine shall 受け付けず、使える項目と演算を示す。

### Requirement 4: 社名で探せる（短い語も取りこぼさない）
**Objective:** 営業担当として、社名の一部から企業を探したい。建設や商事のような短い語でも。
1. When 社名の一部を指定する, the List Engine shall 該当する先頭50社（登録順）と件数を返し、続きのページも返す。
2. When 指定した語が2文字以下である, the List Engine shall 3文字以上の語と同じく、該当する企業を取りこぼさずに返す。
3. When 全角と半角、ひらがなとカタカナ、大文字と小文字だけが違う語で探す, the List Engine shall 同じ企業を返す。
4. When 3文字以上の語で探す, the List Engine shall 先頭50社を50ms以内に返し、件数を、当たりが全体の5%以下の語では100ms以内、それを超える語では300ms以内に返す。
5. When 2文字以下の語で探す, the List Engine shall 先頭50社も件数も500ms以内に返す。
6. If 該当する企業がない, then the List Engine shall 結果なしとして返し、検索できなかった場合と区別する。
7. If 検索語に英数字・かな・漢字が1文字も含まれない, then the List Engine shall 受け付けず、理由を示す。

### Requirement 5: 活動を記録でき、企業の状態と食い違わない
**Objective:** 営業担当として、架電結果を数秒で残し、次の予定まで決めたい。
1. When 架電結果などの活動を記録する, the List Engine shall 活動を追記し、同じ確定の中で企業の状態・最終活動日・次回対応日を更新する。
2. If 活動の記録が途中で失敗した, then the List Engine shall 活動も企業の状態も変えない。
3. The List Engine shall 記録した活動を書き換えも削除もしない。ただし、個人情報の消去（7.3、7.5）によるメモの消去を除く。
4. When 活動の取り消しを記録する, the List Engine shall 企業の状態・最終活動日・次回対応日を、取り消されていない活動だけを記録順に適用した値へ戻す。残る活動がなければ、登録時の状態へ戻し、最終活動日と次回対応日をなしにする。
5. When 活動を1件記録する, the List Engine shall 10ms以内に確定する。
6. While 別のアプリが同じ保存先から一覧を読み取り続けている間も, the List Engine shall 活動の記録を待たせず、前項の目標以内で確定する。
7. If アプリが異常終了した, then the List Engine shall 次の起動で、確定を返した記録を失わず、確定していない記録を半端に残さない。
8. The List Engine shall 電源断のときに直近の確定を失いうる範囲を、利用者向けの文書に明記する。

### Requirement 6: リストを作ってまとめて操作できる
**Objective:** 営業担当として、絞り込んだ企業を架電リスト（その時点の結果を固定したもの）にして、担当や状態をまとめて変えたい。
1. When 絞り込み結果から最大10万社のリストを作る, the List Engine shall 1秒以内に作成する。
2. When リストの企業の担当営業や状態をまとめて変更する, the List Engine shall 10万社を、中央値で2秒以内、95%値で3秒以内に、全社成功か全社失敗のどちらかで確定する。
3. The List Engine shall 同じ企業を複数のリストに入れられるようにし、リストを削除しても企業と活動を消さない。
4. While 企業が除外（連絡停止）の状態である, the List Engine shall 一覧・リストの作成・一括変更の既定の対象から外し、含めると明示されたときだけ対象にする。
5. If 活動の記録または一括変更が、除外の企業の状態を変えようとした, then the List Engine shall その活動または一括変更の全体を受け付けず、除外を解く明示的な操作が必要だと知らせる。状態を変えない活動は、除外の企業にも記録できる。

### Requirement 7: 個人情報を区別して扱え、求めに応じて消せる
**Objective:** 営業担当として、担当者や個人事業主の個人情報を、分けて安全に扱い、求めに応じて消したい。
1. The List Engine shall 個人情報の項目に印を付けて企業のほかの情報と区別して保存し、取り出すときは明示的に選ばれたときだけ含める。
2. The List Engine shall 企業に個人事業の印を付けられるようにし、印のある企業の名称・代表電話・ホームページを個人情報の項目として扱う。
3. When 担当者の消去が求められた, the List Engine shall 氏名と連絡先を消し、活動には消去済みの担当者としてだけ残す。消去の指定があれば紐づく活動のメモも消し、消した事実と日時は残す。
4. The List Engine shall 外部へ通信しない。利用状況の送信と更新の確認も行わない。
5. When 個人事業の企業の消去が求められた, the List Engine shall その企業の名称・代表電話・ホームページ、担当者の氏名と連絡先、すべての活動のメモを消す。残すのは、識別番号・消去済みの印・消去の日時と、活動の日時・種類・状態と次回対応日の変化だけとする。

### Requirement 8: 合成データだけで試験と測定ができる
**Objective:** 開発者として、実データの権利に触れずに、445万社規模の試験と測定を再現したい。
1. When 合成データの生成を指示する, the List Engine shall 件数・乱数の種・分布（公的名簿に近い疎な分布、購入リストに近い密な分布）を指定して、同じ指定なら同じ内容の企業を445万社まで作る。
2. The List Engine shall 合成データの法人番号を、国税庁の構成表で未使用とされている番号帯（基礎番号の先頭が6・8・9）から作り、検査用数字を正しく付ける。
3. When 企業を追加する, the List Engine shall 呼び出し側に「合成」か「実データ」の申告を求め、保存先に記録した種別と食い違う追加を受け付けない。

### Requirement 9: 速さの門が測定を再現し、数字を偽らない
**Objective:** 保守者として、速さの主張を、再現できる測定だけで支えたい。
1. When 速さの門を実行する, the Performance Gate shall 環境（機種・OS・使用部品の版）・分布・件数・試行回数・50%値・95%値・最大値を記録に残す。
2. If 目標値を満たさない測定が1つでもある, then the Performance Gate shall 失敗として終了し、実行時に目標を緩めて通すことをしない。
3. If 基準記録より2倍以上かつ1ms以上遅くなった測定がある, then the Performance Gate shall 失敗として終了する。基準記録の更新は、理由を記録して保守者が承認したときだけ行う。
4. If 保存先の空きが測定に必要な量に足りない, then the Performance Gate shall 実行せず、理由を示す。
5. The Performance Gate shall 文書に書かれた測定値が記録と一致することを確かめ、記録のない数字を文書に書くことを許さない。

### Requirement 10: 保存した内容を守る
**Objective:** 営業担当として、何年分の記録でも、更新や障害で失いたくない。
1. The List Engine shall 保存形式に版を持ち、古い版の保存先を新しい版へ、前方にだけ移行できるようにする。
2. When 移行を行う, the List Engine shall 先に元の保存先の複製を作り、失敗したら複製から戻して、整合性検査と件数の一致で戻ったことを確かめる。
3. If 保存先の空きが、書き込む量から見積もった必要量を下回る, then the List Engine shall 書き込みを始めず、理由を示す。
4. If 保存先の整合性検査に失敗する, then the List Engine shall 開かずに壊れていることを示し、複製から戻す手順を案内する。
5. The List Engine shall 利用者が入力した値を、保存先に対する命令として解釈しない。
