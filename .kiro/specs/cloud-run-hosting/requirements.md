# 要件: 無料枠を基本にした自分用の公開（Cloud Run と Turso）

## はじめに

運用者が一人で使う招待制の meibo を、できるだけ無料枠の中でインターネットに公開する。
支出の上限を置いてから公開する。第三者への提供と課金は対象外とする（保存先の規約の確認と、組織の自動作成などの別設計が要る）。

## 要件

### 要件1: 費用の上限
1.1 When 公開の準備をする, the meibo shall Cloud Run の支出上限と通知を設定してから配備する。上限は確認用が月100円、本番が月400円（合計500円）とする。
1.2 While サービスを運用する, the meibo shall 最大1台・最小0台・リクエスト単位の課金で動かす。
1.3 If 支出が上限に達する, the meibo shall 停止を受け入れ、運用者が再開する手順を文書に残す。

### 要件2: 秘密の扱い
2.1 The meibo shall DB の鍵を Secret Manager に置き、専用の実行アカウントにだけ読み取りを許可する。接続先の URL は、無料の版数を超える場合は Cloud Run の環境変数に置いてよい（2026-11-27 改定。URL も要件2.2のとおり記録に出さない）。
2.2 The meibo shall URL・鍵・パスワードをリポジトリ・ログ・作業の記録に出さない。

### 要件3: 利用
3.1 When 利用者が公開URLを開く, the meibo shall ログイン画面を返し、招待された利用者にだけ操作を許可する。
3.2 When 利用者を追加する, the meibo shall 管理 CLI を使い、パスワードは運用者の端末で非表示入力する。

### 要件4: 検証
4.1 When 公開の前に確認する, the meibo shall 手元から実際の Turso Cloud につないだ応答時間を、同じ合成データの手元 SQLite 版と比べる。
4.2 When 配備の後に確認する, the meibo shall 公開URLで、未認証の拒否・ログイン・一覧・検索・活動の記録・再起動後の保持を確かめる。

### 要件5: 確認用と本番の分離（2026-11-27 追加）
5.1 The meibo shall 確認用と本番を、別の Google Cloud プロジェクト・別の DB・別の鍵・別の実行アカウントにする。
5.2 The meibo shall 確認用には合成データだけを入れる。
5.3 When 本番へ反映する, the meibo shall 運用者の確認を得てから行う。
5.4 The meibo shall develop を確認用、main を本番の元にし、main への取り込みに PR と検査の成功を必須にする。

### 要件6: 本番の入口（2026-11-27 追加）
6.1 When 本番を公開する, the meibo shall Identity-Aware Proxy を有効にし、運用者の Google アカウントだけが到達できるようにする。
6.2 If Identity-Aware Proxy を設定できない, the meibo shall 本番を公開せず、運用者の判断を待つ。
6.3 The meibo shall Identity-Aware Proxy を足しても、アプリのログインを残す。
6.4 The meibo shall OAuth クライアントの秘密の値を、画面の記録・ログ・リポジトリに出さない。

### 要件7: 運用（2026-11-27 追加）
7.1 When 運用者が配備先の管理命令を実行する, the meibo shall 配備の設定から鍵の参照を読み、鍵を画面とファイルに出さずに管理CLIへ渡す。
7.2 The meibo shall 停止と再開、支出上限、結果不明と排他の復旧、鍵の差し替え、バックアップと復旧の手順を docs に置く。
7.3 The meibo shall バックアップを新しいディレクトリに作り、上書きも古い保存物の自動削除もしない。
7.4 When バックアップを定期実行にする, the meibo shall 保存先と頻度を運用者が決めてから設定する。

## 対象外

第三者への提供、課金、独自ドメイン、メール・予定の連携、上限に達した後の自動拡張。
