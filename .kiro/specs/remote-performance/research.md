# 調査: ネット越し保存版の応答を速くする（2026-11-27・案は運用者の承認待ち）

## 結論

遅さの主因は、遠隔データベースとの往復の回数が多いこと。認証済みの読み取り1回で34回以上、`/api/summary` で約78回往復し、往復のたびに TCP と TLS を張り直している。

## コードで確認した事実

- `crates/db/src/remote.rs`: 再利用ソケットでの自動再送を避けるため `pool_max_idle_per_host(0)`（意図した安全側の設定）。`prepare` は Describe の往復を行う。
- `crates/db/src/remote/state.rs`: stream を開くたびに外部キー設定を確認して有効化し、自動確定の文は Close で閉じる。
- `crates/app/src/hosted/http.rs`: 静的な画面を含むすべての要求で全体の鍵（gate）を取り、前後で準備確認をする。
- Turso の集計: 要求ごとに鍵の登録・削除と `sessions.last_seen` の更新（各約50ms）、control への stream 開設が約12回。
- 往復数の内訳（コードから算出）: gate 22、認証 12、業務の読み取り 約8〜12、summary の件数 44。

## 案と目標（往復を約28msとした推定。未測定）

| 段 | 内容 | 読み取り | 書き込み・ログイン |
|---|---|---|---|
| 現状 | — | 約1.3秒 | 約1.8秒 |
| 第1段（安全性は不変） | summary の問い合わせをまとめる／Describe の結果を接続内に保持／読み取りの自動確定は外部キー設定を省き1往復／check_ready を1回の pipeline に／データに触れない応答は gate と DB の外で返す／部品をブラウザにキャッシュ | 0.3〜0.45秒 | 0.6〜0.8秒 |
| 第2段（承認が必要） | 接続の再利用（自動再送しないことを障害試験で証明してから）／読み取りは gate を書かずに状態確認だけ／`last_seen` の更新を60秒に1回 | 0.1〜0.2秒 | 0.3〜0.4秒 |

- 第1段の「gate の外で返す」は remote-storage 要件3.3の文言に注記が要る。
- 第2段は要件2.4（再送しない）、3.3（直列化）、無操作期限の精度（±60秒）に関わる。
- 不採用: 鍵を持ち続ける lease（手動復旧と CLI の受け渡しが増える）、埋め込みレプリカ（今の通信層と合わず、起動のたびの全同期と作り直しが大きい）。

## 利用量の見える化（別機能の案）

- Hrana の応答の `rows_read`・`rows_written`・`query_duration_ms` を db 層で合計する（Turso Cloud が値を返すかは最初に確認する）。
- app 層で経路を機能の群に分け、要求数・時間・往復・行数を日と群ごとにメモリで集計し、10分に1回まとめて書く（無料枠の書き込みの約0.4%以下の見込み）。
- 管理者（admin）だけの画面と API に、推定額（下限の推定と明記）と無料枠の使用率を出す。

## 保存をさらに速くする案（2026-11-27 追記・未実装）

改修後の活動の保存1回（26往復）を、試験の代理サーバーで中身まで記録した（commit 8da5183 の写し）。

| 部分 | 往復 | 内容 |
|---|---:|---|
| 排他の取得と認証 | 4 | 準備確認、外部キー設定、gate の登録、session の読み取り |
| 書き込み前の確認 | 7 | `company_detail` で会社・担当者・活動の全件を読む取引（担当者を指定すると同じ読み取りがもう一度） |
| 業務の書き込み | 10 | 外部キー設定、開始、準備3回（接続で初回だけ）、読み1・書き2、確定、close |
| 監査と解放 | 5 | 監査（2）、準備確認、外部キー設定、gate の削除 |

安全の決まりを変えない案（合計で約8往復の削減。保存は約0.6秒になる見込み・未測定）:
1. 書き込み前の確認を、会社の消去状態と担当者の有無だけを読む1文にする（6往復。担当者ありはさらに7往復）。会社が無い・消去済みの応答は今と同じにする。
2. 取引の確定と close を同じ pipeline で送る（1往復）。確定に失敗した場合は close で取り消される。
3. 外部キー設定の確認と取引の開始を同じ pipeline にし、確認に失敗したら取り消す（1往復）。確認の結果を見る前に開始だけが走るため、設計の「確認の応答を受けてから」の文言の見直しが要る。

安全の決まりを変える案（承認が必要。さらに0.1〜0.2秒の見込み・未測定）: 排他つきの経路でも、同じ要求の中だけ接続を使い回す。切れた接続に書き込みを送ると結果不明になり、手動の復旧が要る場合が増え得る。
