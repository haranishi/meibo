# 架電モードの設計

## Boundary Commitments
既存の一覧条件・企業詳細・活動保存を使うUIの操作モードとする。活動の型や保存表を追加しない。
独自項目/出典/認証は各仕様の責任とし、HTTPの権限検査を迂回しない。

## 操作
開始時に表示中の未除外企業IDをキューとして固定する。次ページがあれば取得して続ける。
一覧条件を変えたらモードを終了し、記録中の条件が黙って変わらないようにする。
活動フォームの成功経路でだけ次へ進める。失敗時は既存のdraftと再試行を維持する。
保存中はスキップ/終了の競合を防ぎ、Ctrl/Command+Enterで保存する。
電話なしでも電話を取得したように見せず、スキップできる。

## UX
営業担当が結果を記録し、対象と記録位置を把握したまま次の企業へ移る。
戦略は反復入力の削減、要件は保存/スキップ/終了、構造は一覧から詳細へ、
骨格は詳細上部の位置表示と主ボタン、表層は既存の操作色とフォームを継承する。

## File Structure Plan
- crates/app/ui/call-mode.js, call-mode.css: キューと操作部品。
- crates/app/ui/app.js: 開始/保存成功/条件変更/終了の接続。
- crates/app/ui/index.html, src/server.rs: ボタンと同梱資産の配信。
- crates/app/tests/server.rs: 資産の到達と既存保存境界。

## 検証
実ブラウザで保存成功/失敗からの再試行/スキップ/未保存終了/除外/0件/末尾/次ページを確認。
キーボードと390/768/1440pxで重なり・横溢れ・フォーカス・入力保持を確認する。
