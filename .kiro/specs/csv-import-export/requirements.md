# CSV取込・書出とローカルCLIの要件

依頼根拠は2026-10-23の続行依頼。企業の固定項目を対象とする。画面、API、独自項目、担当者と活動のCSV、実データ接続、公開は対象外。

### Requirement 11: 逐次CSV
1. UTF-8（BOM有無）と明示指定のShift_JIS（Windows-31J）を、置換文字で不正バイトを隠さず扱う。既定はUTF-8。
2. カンマ・引用符の二重化・引用符内改行・CRLF/LF/CRを扱い、不正な引用符・列数・重複/未知の見出し・必須列不足を拒否する。エラーはレコード番号と理由を示し、入力値をログへ出さない。
3. 1レコードの入力を1MiB、列数を13に制限し、ファイル全体をメモリに保持しない。

### Requirement 12: 登録と重複
1. 各行のoriginは必須とし、保存先との不一致を拒否する。名称と都道府県も必須。入力検査・正規化・法人番号検証はcoreのものを使う。
2. 取込は最大500件か入力文字列8MiBのバッチごとに全成功または全失敗で確定する。開始前にcoreの文字列長・正規化後長を使って空きを検査する。失敗したバッチは検索索引・件数を含め残さない。
3. 法人番号の重複は既定で拒否し、明示したskipでは既存行を更新せずスキップする。ファイル内の重複も同じ規則とし、番号なしの同名企業は別企業として扱う。
4. 結果と失敗には確定済みの追加数・スキップ数を示す。失敗前のバッチは残ることを案内し、未確定バッチの数を成功に数えない。

### Requirement 13: 安全な書出
1. 企業のCSV書出は単一の読み取り時点で逐次処理する。除外は明示指定時だけ含め、消去済み企業は出さない。
2. 個人事業は既定で行全体を省き、明示したinclude-personal時だけ名称・電話・URLを含める。担当者・活動・メモは出さない。
3. UTF-8 BOM/CRLFまたはShift_JISで書出し、表せない文字はエラーにする。文字列の数式開始文字（先行する空白を含む）をアポストロフィで保護する。CSVはバックアップではなく、保護した値は再取込でも保持する。
4. CLIの書出は一時ファイルを使い、完了時だけ新規ファイルとして保存する。既存ファイルや入力/DBを上書きせず、失敗時は未完成ファイルを残さない。

### Requirement 14: ローカル操作と検証
1. init/import/export/list（社名検索を含む）/verify/demoをCLIで実行できる。init/demoは既存の保存先を上書きせず、入力値や未知のオプションの誤りは非0で終了する。
2. 合成データでCLIの生成→取込→検索→書出→再取込→整合性検査を通し、重複・途中失敗・文字コード・容量不足・個人情報・既存ファイル保護の回帰試験を用意する。
