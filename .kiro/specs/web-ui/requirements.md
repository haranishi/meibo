# ローカルのブラウザでCRMを試せるようにする

2026-10-23、本人が「ローカルで一旦立ててほしい」と明示した。コマンドを案内するだけで終えず、localhostで動く画面とサーバーを起動し、URLを返す。合成デモだけを対象とする初回の画面。

### Requirement 15: ローカル起動
1. `meibo serve DB --port PORT` で既存の合成DBを127.0.0.1だけにbindし、実際のURLを表示する。既存DBを再生成・上書きせず、実データDBでは起動しない。ヘルスチェックが通るプロセスを残す。
2. 外部フォント・CDN・利用状況送信を使わず、静的ファイルを同梱する。Hostは起動したloopbackのURLだけを受け付け、CORSを開かない。更新は同一Originと専用ヘッダーを必須にする。

### Requirement 16: 企業一覧と詳細
1. 合成データの印、全企業数・有効企業数・電話あり件数を表示し、企業一覧・社名検索・カーソルで次/前のページを操作できる。個人情報はcoreの既定マスクを維持し、消去済みを詳細に復活表示しない。
2. 企業を選ぶと同じ画面の詳細領域に所在地・電話・状態・次回対応・活動履歴を表示する。値はHTMLとして解釈しない。読み込み中・空結果・エラーと再試行を表示する。
3. 企業詳細から架電メモ・営業状態・次回対応日を保存できる。既存のrecord_activityを使い、失敗時は成功扱いせず、成功時は履歴と一覧を更新する。除外の解除などの既存規則を迂回しない。
4. CSVを書出ボタンでダウンロードできる。既存CSVの個人情報・除外・数式保護を維持する。画面からのCSV取込は今回の対象外。

### Requirement 17: 画面と検証
1. キーボード・390/768/1440pxで一覧から詳細へ到達でき、モバイルで本文の横はみ出しや隠れた主要操作がない。フォームのラベル、フォーカス、保存中/完了の通知を用意する。
2. 合成データで実ブラウザの一覧→検索→詳細→記録保存→再読込→CSV書出を検証し、画面画像と独立レビューの証拠を残す。ローカルURLをユーザーへ返す。


### Requirement 18: 営業ワークスペース
1. 上部に全体検索、別段にホーム/取引先/次回対応の実動するナビを用意する。ホームに実データの状態別件数と対応予定、最近開いた取引先を表示する。架空の売上・目標・未実装の商談オブジェクトは出さない。
2. 取引先一覧を画面幅いっぱいの密な表にし、リストビュー（全件/未着手/商談中/電話あり/予定あり）、検索、表示件数、更新、新規登録、CSVを書出を置く。絞込はサーバー側で適用し、ページをまたいでも維持する。
3. 社名検索はすべての取引先を対象とし、その対象を検索欄に明示する。検索実行時には絞込を解除して案内し、ビュー/絞込変更時には検索を解除して案内する。coreが支えない検索と絞込の併用を無言で無視しない。
4. 企業選択で独立した全幅レコード画面を開く。上部に企業名・主要項目・記録への操作、営業段階の表示、下部に詳細/関連タブと活動入力/履歴を配置する。一覧へ戻ると検索・ビュー・ページを維持する。
5. 既存のメモ/状態/予定の保存、個人情報マスク、消去済み404、CSV保護を維持する。保存失敗時の下書きと再試行、保存中の画面切替抑止も保つ。
6. 新規取引先のダイアログから合成デモの企業を登録できる。名称・都道府県を必須、法人番号・電話・Webサイトを任意とし、重複/入力不正を画面に示す。失敗時は入力を保つ。登録後はその企業を開き、再読込後も残る。
7. 390/768/1440pxで一覧/詳細/ナビ/フォームを実操作でき、文書の横はみ出しやモーダルからの操作不能がない。キーボード、フォーカス復帰、ラベル、選択中タブ、通知を確認する。
