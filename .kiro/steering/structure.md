# 構成

kintai・kamokuと同じ流儀の Cargo ワークスペース。クレートは責務ごとに分け、中心（core）は外部への依存を持たない。

## クレートの役割（計画。作るのは各仕様のタスクから）

- `core`: 型・保存・一覧クエリ。画面も通信も知らない。
- `import`: CSVと公的データの取込器。coreの追加口だけを使う。
- `app`: CLI とローカルサーバー。coreの同じ検索を呼ぶ。
- `xtask`: 点検・測定・変異試験の道具。Rustで書く（別言語の道具を足さない）。

## 置き場の決まり

- `docs/`: 判断の理由・測定・権利確認だけ。コードを読めば分かることは書かない。1ファイル100行以内。
- `docs/benchmarks.md`: 測った数字だけ。測っていない「高速」は書かない。
- `docs/legal/`: 出典の規約、商標、個人情報の確認記録。確認日と一次資料を必ず書く。
- `.kiro/`: 仕様。`.agent-harness/`: 実行記録と契約。

## 依存の向き

`app` → `core` ← `import`。`core` は `app` と `import` を知らない。UIは `app` の公開面だけを呼ぶ。
